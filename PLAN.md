# Spaceman MVP Plan

## The First Version Proves One Architectural Claim

Ghostty uses native macOS tabs. macOS exposes those tabs as separate accessibility windows, so a
window manager that equates one `AXWindow` with one tile eventually allocates empty tiles. Spaceman
will instead give each tile a stable logical identity and treat the current accessibility window as
a replaceable physical binding.

The MVP is a signed Swift menu-bar application that automatically tiles ordinary windows on one
display, responds to window creation and destruction, and keeps a multi-tab Ghostty window in one
unchanged tile. It will use the Accessibility API and one widely used private function for stable
window IDs. It will not require disabling SIP.

After completing this plan, a contributor can run Spaceman beside Ghostty, press `Cmd+T`, switch
tabs repeatedly, and observe that the terminal keeps the same frame while the layout still responds
correctly to real windows.

## Product Principles

1. **Logical slots outlive physical windows.** A tab switch changes a tile's physical binding, not
   the workspace tree.
2. **Observation invalidates; reconciliation decides.** Accessibility notifications are unreliable
   and reordered. They trigger a fresh snapshot rather than directly editing one window in place.
3. **One transaction produces one layout.** Discovery, tab replacement, insertion, removal, and
   layout calculation commit together before any frames are written.
4. **Refuse ambiguous guesses.** If native-tab identity cannot be reconciled safely, preserve the
   current model and retry after the next event instead of corrupting the layout.
5. **No SIP compromise.** The MVP uses Accessibility APIs and `_AXUIElementGetWindow`; it does not
   inject into Dock or use a scripting addition.
6. **Pure layout, narrow native seam.** Rectangle partitioning and logical reconciliation must run
   in tests without macOS windows.

## MVP Scope

The MVP includes:

- Accessibility permission onboarding.
- Discovery of regular applications and their standard, non-minimized windows.
- Stable physical identity using `(pid, CGWindowID)`.
- One active workspace on one selected display.
- One horizontal or vertical root layout with equal weights.
- Automatic reflow when real windows open or close.
- Focus-next and focus-previous hotkeys.
- A deterministic Ghostty native-tab replacement policy.
- Debounced reconciliation after application, focus, window, and mouse-up events.
- A slow periodic reconciliation as a backstop for missed Accessibility events.
- A menu-bar status item with pause, retile, permission status, and quit actions.
- Stable Developer ID signing for retained Accessibility permission.

The MVP deliberately excludes:

- Virtual workspaces.
- Multiple-display workspace assignment.
- Nested containers and arbitrary tree editing.
- Floating-window rules or a general rule language.
- TOML configuration.
- A daemon, Unix socket, or CLI.
- Native fullscreen and minimized-window management.
- Mouse-driven rearrangement.
- Window gaps, animations, borders, and decoration.
- App Store distribution.

Those omissions keep the first test surface centered on window identity and reconciliation, where the
known failure lives.

## System Shape

```text
NSWorkspace + AXObserver
          |
          v
     MacWindows ----------------------+
     native snapshot                  |
          |                           |
          v                           |
      Spaceman                        |
  reconciliation transaction         |
          |                           |
          v                           |
      Workspace                       |
 stable logical slots                |
          |                           |
          v                           |
        Tiler                         |
 pure target frames                  |
          |                           |
          +------> MacWindows --------+
                    frame writes
```

### `MacWindows` Owns Native Reality

`MacWindows` is the only module that knows about `AXUIElement`, `AXObserver`, `NSRunningApplication`,
or `_AXUIElementGetWindow`.

Its interface provides:

- A complete snapshot of currently relevant applications and windows.
- The focused physical window for each application.
- Invalidation events that ask the orchestrator to reconcile.
- Frame and focus commands for a physical window.

Its implementation owns:

- One retained Accessibility observer per application.
- Typed attribute reads and writes.
- Retry behavior for `kAXErrorCannotComplete`.
- Coordinate conversion between AppKit and Accessibility spaces.
- The `size -> position -> size` frame-write sequence.
- Suppression of feedback generated by Spaceman's own frame writes.

Accessibility callbacks never mutate `Workspace` directly.

### `Workspace` Owns Logical Tiles

The first `Workspace` is an ordered list rather than a general tree:

```swift
struct Workspace {
    var axis: Axis
    var slots: [Slot]
}

struct Slot: Identifiable {
    let id: UUID
    var weight: Double
    var binding: PhysicalWindow
}

struct PhysicalWindow: Hashable {
    let pid: pid_t
    let windowID: CGWindowID
}
```

Replacing `Slot.binding` preserves the slot ID, order, weight, and target frame automatically. A
later nested layout can reuse this model by making `Slot` a leaf in a tree.

### `Tiler` Is Pure

`Tiler` accepts a display rectangle, axis, and weighted logical slots. It returns one target frame per
slot. It performs no Accessibility calls.

The first algorithm divides available pixels in stable slot order, assigns rounding remainder to the
last slot, and never emits overlapping frames.

### `Spaceman` Owns Reconciliation

`Spaceman` serializes all model changes on the main actor. It receives an invalidation, requests one
native snapshot, reconciles the snapshot with the current workspace, calculates one layout, and asks
`MacWindows` to apply changed frames.

This module owns debounce, cancellation, and generation numbers. An older snapshot or frame job
cannot commit after a newer generation.

## Native Tabs Are Physical Replacements

The first tab-aware application allowlist contains:

- Ghostty: `com.mitchellh.ghostty`
- Fork: `com.DanPristupov.Fork`

The allowlist exists because applications expose native tabs differently. Applying one heuristic to
all applications risks replacing a real top-level window.

For an allowlisted application, each reconciliation reads both `AXFocusedWindow` and `AXWindows`.
The focused ID is always included in the active set because those attributes can disagree during a
transition.

```text
previous focused ID: A
current focused ID:  B
tracked IDs:         {A}
active AXWindows:    {B}

stale: {A}
new:   {B}

Result: replace binding A with B in the same logical slot.
```

Replacement selection follows this order:

1. Prefer the stale physical window matching the application's previous focused window.
2. Otherwise replace only when exactly one bound stale candidate exists.
3. Otherwise do not guess. Preserve existing logical slots and schedule another reconciliation.

The complete transaction is:

1. Capture the previous focused physical ID.
2. Read the current focused window and `AXWindows`.
3. Register the focused physical handle before pruning stale handles.
4. Derive active, stale, and newly observed physical IDs.
5. Replace one logical binding when the rule is unambiguous.
6. Remove genuinely closed windows.
7. Insert genuinely new top-level windows.
8. Store the current focused ID for the next transaction.
9. Calculate layout once.
10. Apply only changed target frames.

Native-tab reconciliation pauses while the left mouse button is down. Dragging a tab out of a tab
group creates intermediate Accessibility states that must not be interpreted as a completed switch.
Mouse-up triggers a fresh reconciliation.

## Native Event Strategy

Spaceman subscribes to:

- `NSWorkspace.didLaunchApplicationNotification`
- `NSWorkspace.didTerminateApplicationNotification`
- `NSWorkspace.didActivateApplicationNotification`
- `NSWorkspace.didHideApplicationNotification`
- `NSWorkspace.didUnhideApplicationNotification`
- `NSWorkspace.activeSpaceDidChangeNotification`
- `kAXWindowCreatedNotification`
- `kAXFocusedWindowChangedNotification`
- `kAXUIElementDestroyedNotification`
- `kAXWindowMovedNotification`
- `kAXWindowResizedNotification`
- A global left-mouse-up monitor
- Wake notification

Every event is an invalidation. A short debounce coalesces bursts. A periodic reconciliation catches
missed close and tab events.

The MVP may make AX calls on the main thread while proving behavior, but the first robustness pass
moves blocking AX reads and writes to one serial worker per application. Model commits remain on the
main actor.

## Milestones

### Milestone 0: Establish A Signed App Skeleton

Deliver:

- Swift package and minimal AppKit menu-bar app.
- Stable bundle identifier `com.kitlangton.spaceman`.
- `LSUIElement = true`.
- Accessibility permission prompt and status display.
- Developer build and signing scripts.

Acceptance:

- Rebuilding and reinstalling with the same identity preserves Accessibility permission.
- The app starts without a Dock icon and can quit from its menu.

### Milestone 1: Observe Native Windows Without Moving Them

Deliver:

- Typed Accessibility helpers.
- `CGWindowID` extraction.
- Running-application discovery.
- Per-app observers.
- A debug snapshot that prints PID, bundle ID, window ID, frame, role, subrole, minimized state, and
  focused state.

Acceptance:

- Opening and closing TextEdit and Ghostty windows updates one coherent snapshot.
- Opening two Ghostty tabs demonstrates the physical-ID behavior in a captured regression fixture.

### Milestone 2: Tile One Display

Deliver:

- Pure `Workspace` and `Tiler` modules.
- Equal horizontal and vertical layouts.
- Frame application with generation cancellation and feedback suppression.
- Pause and retile menu actions.

Acceptance:

- Two ordinary windows divide the visible display exactly once.
- Opening a third window creates three non-overlapping frames.
- Closing one window expands the remaining windows without a persistent gap.

### Milestone 3: Make Ghostty Tabs Correct

Deliver:

- Per-app native-tab policy.
- Previous-focused-ID tracking.
- Atomic physical-binding replacement.
- Mouse-down deferral and mouse-up reconciliation.
- Native-tab regression tests.

Acceptance:

- One Ghostty window with ten tabs occupies one logical slot.
- `Cmd+T`, tab switching, and tab closing never alter the slot count or frame.
- Two separate Ghostty windows, each with multiple tabs, occupy exactly two slots.
- Detaching a tab creates a second slot only after the drag completes.
- A real second Ghostty window is never mistaken for a tab.

### Milestone 4: Add Keyboard Navigation

Deliver:

- Focus-next and focus-previous hotkeys.
- Swap-next and swap-previous hotkeys.
- Axis toggle.
- Hotkey conflict diagnostics.

Acceptance:

- Navigation follows logical slot order, not stale physical IDs.
- Switching a Ghostty tab does not reset focus order or slot weight.

### Milestone 5: Harden And Publish The MVP

Deliver:

- Per-app AX worker isolation.
- Wake and app-hang recovery.
- Structured diagnostic log with redacted window titles by default.
- Signed, notarized release artifact.
- Homebrew cask.
- User guide and issue template with snapshot diagnostics.

Acceptance:

- A wedged application cannot freeze Spaceman's menu or other applications.
- Sleep/wake followed by a retile restores the model.
- A clean machine can install, grant permission, and reproduce the Ghostty acceptance test.

## Test Strategy

The interface is the test surface.

### Pure Tests

- Weighted rectangle partitioning covers every pixel exactly once.
- Insertion and removal preserve stable slot order.
- Physical replacement preserves slot ID, weight, order, and target frame.
- Ambiguous stale candidates do not mutate the workspace.
- An older reconciliation generation cannot commit.

### Recorded Snapshot Tests

Store sanitized snapshots for:

- One Ghostty window with one tab.
- One Ghostty window switching between several tabs.
- Two independent Ghostty tab groups in one process.
- A dragged tab becoming a new top-level window.
- Finder native tabs.
- Ordinary multi-window applications.

Snapshot tests feed native observations into the pure reconciler. They never require Ghostty in CI.

### macOS Integration Tests

A small opt-in suite launches fixture applications and verifies visible frames through Accessibility.
It covers permission denial, app launch, ordinary insertion/removal, frame constraints, and Ghostty
when installed.

## Distribution Decisions

- Language: Swift 6.
- UI: AppKit menu-bar application; add SwiftUI only if settings require it.
- Minimum macOS: 15 unless implementation evidence requires 14 support.
- License: MIT.
- Distribution: signed and notarized direct download plus Homebrew cask.
- Private API: `_AXUIElementGetWindow` only, isolated behind `MacWindows`.
- App Store: unsupported because of the private window-ID function and Accessibility behavior.
- Configuration: compile-time/default settings until the MVP proves the model.

## Risks And Responses

### Accessibility State Is Temporarily Inconsistent

`AXFocusedWindow` and `AXWindows` can disagree. Spaceman includes the focused window in the active set,
debounces bursts, and refuses ambiguous replacement.

### AX Calls Can Block

The tracer bullet may use the main thread for simplicity. Before publication, each app receives an AX
worker so one hung app cannot freeze the manager.

### Native Tabs Vary By Application

The replacement policy is opt-in by bundle ID. Recorded snapshots document each supported behavior.

### Frame Writes Generate More Events

Each target frame carries a reconciliation generation. Matching move/resize events are recognized as
manager output and do not start an unbounded loop.

### macOS Has No Public Spaces Management API

The MVP has one workspace. Later virtual workspaces will move inactive windows off-screen rather than
depending on native Spaces or disabling SIP.

### Signing Determines Permission Stability

Development and release builds use a stable signing identity from the first milestone. Ad-hoc builds
are not treated as the normal development path.

## Post-MVP Direction

Only after the native-tab MVP is stable:

1. Replace the flat workspace with nested weighted containers.
2. Add multiple displays.
3. Add virtual workspaces without native Spaces.
4. Add explicit floating rules.
5. Add a versioned TOML configuration.
6. Add a Unix socket and CLI.
7. Add visual borders and optional layout feedback.

The first post-MVP design review must preserve the central invariant: physical accessibility windows
are observations, while logical slots are product state.
